Forth shift-register debouncer (db-timer.fs)

Each timer tick (5 ms) the ISR shifts a 4-bit history register left and OR's in the inverted P2.0 sample (1 = pressed). When the history fills with all 1s the press is accepted; when it clears to all 0s the release re-arms the detector.

: shift-isr ( -- )
  shift-hist @ 1 lshift                  \ shift window left
  switch? 0= 1 and or                    \ append inverted sample (1=pressed)
  $F and shift-hist !                    \ keep low 4 bits
  shift-hist @ $F = shift-on @ 0= and
    if  1 press-count +!  1 shift-on !  then    \ rising edge
  shift-hist @ 0= shift-on @ and
    if  0 shift-on !  then                      \ falling edge
;

Compared with Ganssle's 16-bit pseudocode (State = (State<<1) | !RawKeyPressed() | 0xe000; if (State==0xf000)…), this Forth version uses a 4-bit window and tracks the armed/idle state in a separate shift-on flag instead of detecting the released→pressed transition pattern with the 0xe000 mask. Same shape, simpler arithmetic.

Pin high (released, pull-up) Pin low (pressed) history bit = 1 history bit = 0 rising-edge fire falling-edge re-arm

What to watch for

  • Idle (ticks 0–9): pin high, sample 0, history stays 0000.
  • Bouncing press (ticks 10–17): pin flicks low/high; samples alternate; history walks through dirty patterns like 0001 → 0010 → 0101 → 1011 but never hits $F, so nothing fires.
  • Settled (tick 18): four consecutive 1s have shifted in, shift-hist == $F and shift-on == 0 — fire the rising edge: press-count increments, shift-on latches to 1.
  • Held (ticks 19–34): history saturated at $F; no further events even though the ISR keeps running every 5 ms.
  • Bouncing release (ticks 35–42): zeros shift in past the bounces; history drains from $F down through intermediate values.
  • Re-armed (tick 43): shift-hist == 0, shift-on clears — ready to detect the next press.
